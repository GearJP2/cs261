# INT-03 — Demo runbook Sprint 1

เจ้าของการดำเนินเดโม: เกียร์  
ผู้ร่วมเดโม: วี, เนท, ออสติน และเจ้าของ Backend ของแต่ละ US

ใช้เอกสารนี้กับ Issue #30 หลัง INT-02 ผ่าน ไม่ใช้เป็นการยืนยันว่า TU integration ผ่านก่อนมี TU API

## ก่อนเริ่มเดโม

- checkout commit ที่ INT-02 ระบุว่า regression ผ่าน
- รัน `make verify`, `make up` และ `make smoke` แล้วเก็บผล
- เตรียมสองบัญชีทดสอบแยกกัน: Host และ Applicant
- เตรียมกีฬา/สนาม active, เวลาเปิดที่เลือกได้ และตัวอย่างสนาม/เวลาที่ต้องถูกปฏิเสธ
- ปิดหรือปกปิดข้อมูลส่วนตัว, credential, session cookie และ token ก่อนบันทึกภาพหรือวิดีโอ

## ลำดับเดโม

| ลำดับ | ผู้ดำเนินการ | สิ่งที่แสดง | ผลที่คาดหวัง | สถานะ |
| --- | --- | --- | --- | --- |
| 1 | เกียร์ | หน้าเริ่มต้นและวิธีรัน | แอปและ health check ทำงาน | Not run |
| 2 | วี/เนท | เลือกกีฬา สนาม และเวลาเปิด | เห็นเฉพาะสนามที่ตรงกีฬา; วันหรือเวลาปิดถูกแจ้ง | Not run |
| 3 | Host | สร้าง Party | ไปหน้า detail; Host เป็นสมาชิก; จำนวนที่ว่างถูกต้อง | Not run |
| 4 | Applicant | เปิด Party เดียวกันและส่งคำขอ | เห็น Pending; จำนวนที่ว่างไม่ลด | Not run |
| 5 | Host | แก้ชื่อ/เวลา/สนาม | บันทึกเมื่อถูกต้อง; แสดง error และคงฟอร์มเมื่อผิด | Not run |
| 6 | Host | ยกเลิก Party | สถานะ Cancelled; applicant ส่งคำขอใหม่ไม่ได้ | Not run |
| 7 | Applicant | เปิด Profile ของ Host | แสดงชื่อ กีฬา เครดิต; ไม่มีข้อมูลส่วนตัว | Not run |
| 8 | เกียร์/พี | Login/Logout | แสดงเฉพาะ flow ที่ provider อนุมัติจริง; ถ้ายังเป็น fixture ให้ประกาศว่า `Blocked: TU API` | Blocked |

## ข้อความเปิดเดโมที่ใช้ได้

> รอบนี้เดโม flow สร้าง Party → ส่งคำขอ Pending → แก้ไข/ยกเลิก โดยใช้ข้อมูลทดสอบในระบบ ส่วนยืนยันตัวตนกับ TU provider จริงยังไม่เดโม เพราะรอช่องทาง API และสิทธิ์เข้าถึงจากมหาวิทยาลัย

## หลักฐานที่ต้องเก็บ

- commit SHA และผล `make verify` / `make smoke`
- ภาพหรือวิดีโอแต่ละช่วงที่ไม่เผยข้อมูลลับ
- รายการบั๊กที่ยังเปิดอยู่ พร้อม owner และผลกระทบต่อ demo
- ข้อจำกัดที่ยืนยันแล้ว: ไม่มีระบบจองสนาม, ไม่มีวันหยุดพิเศษ, Pending ยังไม่จองที่ และ TU provider ยังรออนุมัติ

## เกณฑ์ตัดสินก่อนส่งเดโม

เดโมผ่านเมื่อขั้น 1–7 ที่อยู่ใน scope ผ่านบน commit เดียวกัน และขั้น 8 ระบุผลตามความจริง หาก TU API ยังไม่พร้อม ให้รายงาน `Blocked` พร้อมเหตุผลและหลักฐานการขอสิทธิ์ แทนการใช้ mock แล้วอ้างว่า login มหาวิทยาลัยใช้งานจริง
