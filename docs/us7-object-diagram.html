Object UML — แก้ไขหรือยกเลิกปาร์ตี้

ตัวอย่างวัตถุจริงในระบบ ณ ช่วงก่อน Host แก้ไข/ยกเลิก และหลังยกเลิกสำเร็จ

Object diagram แสดง instance และค่าข้อมูลตัวอย่าง ไม่ใช่ class diagram หรือขั้นตอนการเรียก API ใช้ตรวจความสัมพันธ์ที่ US7 ต้องรักษา: Host เป็นเจ้าของ Party, สมาชิก active นับความจุ, และการยกเลิกไม่ลบประวัติสมาชิกหรือคำขอ

1. Snapshot ก่อนแก้ไขหรือยกเลิก

Party ยังไม่เริ่มและยังไม่ถูกยกเลิก จึงเป็นข้อมูลที่ Host แก้ไขได้เมื่อผ่านกฎเวลา สนาม และความจุ

2. Snapshot หลัง Host ยกเลิกสำเร็จ

การยกเลิกเปลี่ยนเฉพาะข้อมูลของ Party เป็น Cancelled และเก็บ Membership/JoinRequest เพื่อเป็นประวัติและให้ API อ่านสถานะได้

สี่เหลี่ยมมีชื่อขีดเส้นใต้ = object instance · เส้นลูกศร = object อ้างอิงกัน · ค่าที่ระบุว่า derived คำนวณจากข้อมูลจริง ไม่ได้เก็บเป็นคอลัมน์แยก
